# Phase 2 — OpenCode pilot notes (friction log)

The pilot ported the whole surface (not just the lead+senior slice) because the generator does all
8 units at once. Output lives in `.opencode/agents/*.md` (subagents) and `.opencode/commands/*.md`
(slash commands), generated by `npm run build:agents` and guarded by `npm test` (Layers 1–3).

## What was verified against current docs (Sept 2026)

- **Agent files:** `.opencode/agents/<name>.md` (plural `agents`), YAML frontmatter. Fields used:
  `description`, `mode: subagent`, `model` (`provider/model-id`), `tools` (map name→bool),
  `permission` (edit/bash/webfetch → allow). Body = system prompt.
  Source: opencode.ai/docs/agents.
- **Commands (skills):** `.opencode/commands/<name>.md`, invoked `/<name>`, frontmatter `description`
  (optional `agent`, `model`, `subtask`). Body = the command prompt. Source: opencode.ai/docs/commands.
- **Subagent invocation:** `@agent-name` (user) or the **Task tool** (a primary agent delegates by
  description). So the Claude `Agent({ subagent_type })` call maps to `task({ subagent })`.

## Seam substitutions applied (adapters/opencode.json → `body`)

1. **Paths (seam 4):** `.claude/agents/` → `.opencode/agents/`; each `.claude/skills/<x>/SKILL.md` →
   `.opencode/commands/<x>.md`.
2. **Spawn (seam 2):** `Agent({ subagent_type: … })` → `task({ subagent: … })` (all spacing variants +
   the multi-line block); `(Agent tool)` → `(Task tool)`.
3. **Tool names (seam 3):** `Agent`→`task`, `WebSearch`/`WebFetch`→`webfetch`,
   `TaskCreate/Update`→`todowrite`, `TaskList/Get`→`todoread`, `AskUserQuestion`→"an interactive
   question". Compound bullet forms collapsed (e.g. `` `WebSearch` / `WebFetch` `` → `` `webfetch` ``).
4. **Frontmatter (seams 1/5/6):** rebuilt per unit — tier→model via `tiers.json`, `tools` map with the
   granted set true and the rest of `allTools` false (real restriction), permission map.
5. **Model prose (seam 5b):** left as-is. OpenCode's tiers map to Anthropic models, so "Opus/Sonnet/
   Haiku" in prose stay accurate. (For a GPT-backed provider this would need neutralizing — see Codex.)

## Friction found (feeds the adapter abstraction)

- **No `AskUserQuestion` equivalent.** OpenCode agents ask in plain text; the tool name has no
  counterpart, so it renders as prose ("an interactive question"). Captured as a seam-3 "absent tool"
  case — the fallback is prose, not a tool.
- **Tool-name vocabulary is lowercase and partly many-to-one** (`TaskCreate`+`TaskUpdate`→`todowrite`),
  which produced duplicated bullets until compound substitutions were added. Lesson: seam-3 needs
  compound-aware rules, not just per-token, for clean prose.
- **Tool restriction fidelity.** OpenCode restricts via the `tools` map; we enumerate `allTools` and
  set the granted set true / rest false. This is stricter than the Claude `tools:` allowlist reads,
  but matches intent (junior = read/edit/grep/glob/bash only). Re-check if OpenCode adds tools.
- **Model IDs are placeholders** in `tiers.json` (`anthropic/claude-opus-4-1`, etc.) — re-verify the
  exact provider/model IDs at real port time; they drift.
- **Skill→command vs primary-agent.** We chose `/commands` (slash parity with Claude skills). The
  deterministic non-agent work in `/translate` (scope calc, final verify/build, commit) runs as the
  command body's instructions; a live run may want a dedicated primary agent instead. Revisit after L5.

## Validated against the real CLI (OpenCode Desktop v1.18.31 / core 1.4.0)

Run on the actual `opencode` CLI, not just doc-reading:

- **`opencode agent list` discovers and parses all four generated agents** —
  `translate-lead/senior/junior/researcher`, each as `(subagent)`. The real tool accepted the
  frontmatter (mode/model/tools map/permission) with no parse error. This is a stronger Layer-2 pass
  than the offline lint.
- **A live `opencode run` executes and produces correct output** — a chrome-translation smoke prompt
  returned proper German (`Einstellungen` / `Speichern` / `Alle Rechte vorbehalten`).
- **Behavioral fixture smoke passed.** Running the ported `translate-senior` on the eval-fixture via
  `opencode run` (on the weak free model `nemotron-3.5-lightning-free`) produced a correct German
  `de.json` — glossary term honored (`melden Sie sich an`, not `einloggen`), formal register (Sie),
  `{username}` placeholder preserved — grading **1 violation** on `eval-assert.mjs` (`nav.dashboard`
  kept as the German loanword "Dashboard", a defensible choice, not a source-leftover). So the port is
  behaviorally validated end-to-end on OpenCode even at the lowest model tier.
- **Models inherit the default (unresolved).** OpenCode's tiers are left unresolved in `tiers.json`, so
  the generated agents omit `model:` and inherit whatever model OpenCode is configured with — no
  hardcoded IDs, no auth needed to get a working tree. Pin per-tier models with `npm run models` when
  you want the cheap/expensive tiering back.
- **Finding — subagents aren't directly runnable via `run --agent`.** `opencode run --agent
  translate-junior` warns *"is a subagent, not a primary agent. Falling back to default agent"* and
  runs the default primary instead. Subagents are reachable only through a **primary** agent's Task
  tool / `@mention`. So the panel's real entry point is the **`/translate` command** (a primary),
  which then delegates to the workers — exactly the design, but it means a Layer-5 behavioral run must
  start from the command, not `--agent translate-lead`.
- **Model IDs unverifiable here.** `opencode models` listed only free `opencode/*` models (no paid
  provider authed), so the `anthropic/claude-*` tier IDs in `tiers.json` couldn't be confirmed against
  the provider list — the `provider/model-id` *format* is correct; the exact IDs remain re-verify-at-
  port-time placeholders.

## Not done here (out of scope for a deterministic build)

- **Layer 5 — live behavioral run.** Running the ported panel on the OpenCode CLI against
  `examples/eval-fixture/` and re-running `tests/eval-assert.mjs` (expect 0 violations) needs OpenCode
  installed and costs tokens — it's the pre-release runbook, not part of `npm test`. See
  `examples/eval-fixture/README.md`.
